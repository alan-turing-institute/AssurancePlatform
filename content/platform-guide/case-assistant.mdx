The Case Assistant is a chat panel on the case page.
It reads the case you have open and helps you work on it.
You can ask it questions about the case, ask it to check the case against a set of rules, ask it for techniques that could produce evidence for a claim, and ask it to reword an element or add one.
It never changes the case itself: when you ask for a change, it suggests one, and nothing is saved until you choose **Apply**.
It does not judge whether the case is good enough.
That judgement stays with you and your reviewers.

## Turn it on

The assistant is off until you turn it on.
Open **Settings > Plugins** (`/dashboard/settings/plugins`) and switch on **Case Assistant**.
Your site's operator can withhold the assistant from everyone.
When they have, its card reads "Unavailable on this deployment" and the switch is locked.
Your organisation or your team can also turn it off for you.
Its card then reads "Turned off by your organisation" or "Turned off by your team", and you cannot turn it on yourself.

## Connect a model

The assistant answers with a model you connect yourself.
TEA does not supply one.
If you ask a question before one is set up, the panel tells you so and links to the settings.
Once the Case Assistant is on, an **AI models** section appears below the plugin cards.

### Quick setup

The fastest route is an OpenRouter key.
Paste it into **Quick setup** and choose **Set up**.
TEA tests the key first and saves nothing if OpenRouter refuses it.
It then adds a connection and fills in the recommended model for each of the three jobs described below.

### Add a connection yourself

Choose **Add connection**, pick a type, give the connection a label and fill in the fields that type needs.

| Type | What it is | Address | Key | Jobs it can do |
|---|---|---|---|---|
| OpenRouter | One key reaches many hosted models. | Fixed | Required | Chat, Ranking, Search |
| Ollama | A model server you run yourself. | You enter it | Optional | Chat, Ranking, Search |
| OpenAI-compatible | Any server that follows the OpenAI API, such as vLLM. | You enter it | Optional | Chat, Search |
| Anthropic | Claude models. | Fixed | Required | Chat |
| OpenAI | OpenAI's own models. | Fixed | Required | Chat |

Each connection has **Test**, **Edit** and **Remove** buttons.
**Test** checks that the connection works and loads the list of models you can choose from.
A site normally allows only secure (`https`) addresses on the public internet.
A model server on a private network, or one without `https`, works only if the site's operator has allowed it.

TEA stores your key encrypted and does not show it again.
To change it, choose **Edit**, then **Replace key**.

### Choose a model for each job

The **Jobs** list sets which connection and model does each of three jobs.
For each job, pick a connection, pick a model and choose **Save**.
A job lists only the connections that can do it.
Each model list marks the recommended model where there is one, and you can type a model name that is not in the list.
OpenRouter has a recommended model for all three jobs, and Ollama has one for Ranking and Search.
The other connection types have none.

| Job | What it does | If it is not set |
|---|---|---|
| Chat | The model the assistant talks with. | The assistant cannot answer. Chat is the one job you must set. |
| Ranking | Puts the techniques the search finds in order, best first. | Techniques stay in the order the search found them. |
| Search | Lets the assistant find techniques by meaning, not only by keyword. | Techniques are found by keyword only. |

Ranking and Search are optional, and you can switch either to **Off**.

#### The search check

Search by meaning works only if your search model gives the same results as the model the techniques library was built with.
When you save a new search model, TEA checks this by comparing the results for a few fixed test sentences.
The job then reads **Check passed** or **Check not passed**.
Until a check has passed, techniques are found by keyword only.
If the check does not pass, choose the recommended search model where the list marks one, or choose **Check again** to run it once more.
Where the list marks none, choose the model the techniques library was built with, or one that gives the same results.
A passed check stops counting if the techniques library switches to a different search model or changes its test sentences.
The status then says that the check no longer counts, and you can run it again.

## Open the assistant

On a case page, choose **Case assistant** (the robot icon) in the toolbar.
The panel opens at the right of the page, over the right-hand part of the diagram.
It does not lock the rest of the page, so you can keep working on the case while it is open.
On a narrow screen it fills the page, and you close it to see the diagram.
Closing the panel keeps the conversation, and what you did with each suggestion, until you reload the page.
Choose **New chat** at the top of the panel to clear the conversation and start again.

## What you can ask

Before your first message, the panel offers a few questions you can send with one click.
Select an element on the diagram and the panel names it at the top, so that you can ask about it directly.
Press **Enter** to send a message and **Shift+Enter** for a new line.
Choose **Stop** to end a reply early.

The assistant can do five things.

- **Read the case.**
  It reads the whole case, or one element and the elements directly beneath it, to answer questions such as which claims lack evidence.
- **Check the case against the rules.**
  Ask it to check the case.
  The result lists findings by rule and element, each with a reason and a suggested fix, together with gaps you have already marked as **Needs support** and questions for you.
  TEA checks some rules itself.
  The assistant applies the rest with its own judgement, so those findings depend on the model you chose.
- **Suggest techniques for a claim.**
  This works only when your site offers the techniques library.
  Select an element and ask for techniques, or type the claim in the chat.
  The assistant is instructed to recommend only techniques the library returns.
  It shows up to five, each with its goals and, where the library gives one, a link.
  It is also instructed to tell you when search or ranking was not used.
- **Report automated check results.**
  This works when you have also turned on the Claim/Evidence Health plugin and the case has claims with checks or results.
  For each property claim, the assistant can report the latest result (pass, marginal, fail or indeterminate), the check the claim is bound to, when the result was taken and whether it is out of date.
  It reads the results afresh each time you ask, because they change.
  A result reports what a check found and does not make a claim true or false.
  The [health plugin page](/docs/technical-guide/architecture/health-plugin) explains how results are recorded.
- **Suggest a change.**
  This works when you can edit the case.
  Ask it to reword an element or to add one, for example "reword P1 so it is more specific" or "add evidence for this claim".
  It replies with a suggestion card that you can apply or dismiss.
  [Suggested changes](#suggested-changes) describes the cards.

## Suggested changes

A suggestion appears in the chat as a card, beneath the tool's own row.
For a rewording, the card shows the element's label, its current text and the suggested text.
For a new element, it shows which element the new one would go beneath, the type of the new element and its text.
Case text on a card is plain text, so a link or an image in it is not made active.

The card has two buttons, **Apply** and **Dismiss**.
Nothing in the case changes until you choose **Apply**.
**Apply** saves the change as if you had typed it into the element's edit form.
The diagram updates, and the toolbar's **Undo** reverses the change like any other edit.
After you choose, the card reads **Applied** or **Dismissed**.
Each suggestion is applied on its own, and there is no button to apply them all.
The assistant knows which suggestions you applied and which you dismissed, so you can carry on the conversation from there.

If the element changed after the suggestion was made, here or in another tab, **Apply** saves nothing.
The card then says that the element has changed since the suggestion, and you can ask the assistant again.
If the save fails for another reason, the card shows the reason and keeps its buttons, so you can try again.

### What it can suggest

- **A new wording** for an element's description, assumption, justification or context entries, where that kind of element has the field.
  A suggestion gives the whole new text of each field it changes.
  It cannot empty a field, and the text is at most 5,000 characters, which is what TEA saves in one field.
- **A new element** beneath an existing one: a strategy, a claim or evidence.
  TEA allows a strategy or a claim beneath a goal, a claim beneath a strategy, and a claim, evidence or a strategy beneath a claim.
  The new element gets its label from TEA, as it does when you add one yourself.
  A new element carries a description only; add a link to evidence in the element's own form.

When you ask for something the assistant cannot do, it says so and shows no **Apply** button.
It does not suggest deleting, moving or detaching elements, counter-arguments, a change to an element's status or label, evidence links, or changes to away goals and modules.
It does not reword text that refers to a defined term, or a context list that defines terms, because the assistant reads a plain copy of that text and a rewording would break the reference.
Edit those in the element's form.

The assistant makes suggestions only when you ask for a change.
Asking it to check the case gives the findings as before.

### Who can use it

Suggestions are offered only to people who can edit the case.
With view or comment access, the assistant stays read-only and answers questions as before.
Applying a suggestion goes through the same save as the edit form, so the usual checks of your access to the case still apply.
Your site's operator can also switch suggestions off for everyone, which leaves the assistant read-only.

## What it can see

The assistant reads the case with your own access, so it can read only what you can open.
It sees only the case you have open, and not your other cases.
It also receives the element you have selected: its label, type and text.
It does not read comments.

## What is kept and what is sent

- Your key is stored encrypted and is not shown again.
- Your conversations stay in your browser tab.
  TEA does not store them, and reloading the page clears them.
- TEA does not write your questions or the assistant's replies to its logs.
- The provider or server your connection points at receives what the assistant sends it: your messages, the earlier messages in the chat, and whatever the assistant reads to answer, such as the case, the selected element and automated check results.
  It receives them on the terms that apply there, so check how that provider or server handles them.
- When you ask for techniques, the claim also goes to the techniques library service and to the models you chose for search and ranking, where those jobs are in use.
  With an element selected, the claim is that element's text, unless you typed a claim of 40 characters or more in the chat, which is sent instead.
  With no element selected, it is the claim you typed.
  Only the first 2,000 characters are sent.

## Links and images in replies

Replies are shown as formatted text, with some limits.
A link opens in a new tab only after you confirm it in a dialog that shows the address.
Only web (`http` and `https`) and email (`mailto`) links work, and any other link appears as plain text.
Images are never loaded, and an image appears as its description text.
Raw HTML appears as text.

## If a reply fails

If your provider refuses a request, the panel shows the provider's own reason, with your key and the connection's address removed.

## For operators

An operator can withhold the plugin, allow model servers on a private network, switch the suggested changes off and set the assistant's limits.
The [Case Assistant page in the Technical Guide](/docs/technical-guide/architecture/case-assistant) describes these settings.

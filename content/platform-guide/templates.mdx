A pattern is an argument set aside for reuse.
It is built in the same editor as an assurance case, from the same goals, strategies, claims and evidence, and it is shared and permissioned in the same way.
What differs is where it appears: a pattern is left out of **My Assurance Cases**, is listed under **My Patterns**, and carries a **Pattern** badge wherever it is listed.

## How a pattern looks in the editor

When you open a pattern, a small notice at the top left of the canvas reads "This is a pattern."
Everything else in the editor works as it does for a case.

## Placeholders

A placeholder is an element that the person using the pattern writes.
It marks a place where the pattern needs your own claim, strategy or evidence, and it is how a pattern says what is left to fill in.

### Mark a placeholder in a pattern

Open an element in a pattern and choose its edit button.
Switch on **Placeholder: the person using this pattern writes this**.
A **Hint for the person filling this in** box appears; use it to say what to write, in up to 500 characters.
The element may keep sample text, or have none.
Switch the placeholder off again to take the marker and its hint away.
An element with no text needs its description written first; the dialog says so beside the switch.

A placeholder is drawn with a dashed outline and a **To fill in** badge, in a pattern and in a case alike.
Hover over the badge, or tab to it, to read the hint.

### Fill a placeholder in a case

A case started from a pattern keeps each placeholder as a placeholder, with its hint, and every element in it counts as coming from the pattern.
A placeholder with no text shows its hint, in italics, where the text will go.
In the edit dialog the hint is shown above the description.

Writing the description of a placeholder takes the marker off.
That holds whichever way you write it: in the edit dialog, in the JSON editor, or by applying a suggestion from the Case Assistant.
Changing only the assumption, justification or context leaves the marker on, and so does saving the description unchanged.
Emptying the description does not count as writing it.
**Undo** puts the marker back, and **Redo** takes it off again.

A case with elements still to fill in cannot be published; see [Publishing and Discover](/docs/platform-guide/publishing-and-discover).

### In a pattern, nothing clears by itself

Writing text into a placeholder in a pattern does not take the marker off.
The author decides, with the switch, whether the person using the pattern writes the element.
The dashed outline shows which elements are still placeholders.
A pattern is not held back from publishing by its own placeholders.

### A new blank case or pattern

A new blank case or pattern starts with one element, the top-level goal **G1**, as a placeholder with no text and the hint "Describe your top-level assurance goal".
In a case, writing the goal takes the marker off.
In a pattern, either write the goal and switch the placeholder off, or leave it for the person using the pattern.

### Export and import

An export keeps each placeholder's marker and hint, and an import restores them.
A file that holds a placeholder is written as export version 1.1, and a file that says 1.0 but holds one is refused, because an older reader would drop the markers.

## Variables

A variable is a detail that a pattern leaves for the person using it to set once, such as the name of the system.
It is a defined term with its variable switch on: wherever the term is mentioned, the case shows its value, and changing the value once updates every mention.
[Building a case](/docs/platform-guide/building-a-case) describes defined terms.

### Mark a variable in a pattern

Open the goal, strategy or claim that should define the variable and choose its edit button.
Name a context entry, as for any defined term, and switch on **Variable: show its value wherever it is mentioned**.
Mention the name in the descriptions of the elements beneath it by typing `{` and choosing it from the list.
Evidence beneath a claim can mention it too.
The value can stay empty, or hold an example for the person using the pattern to replace.

### Give values when you start a case

Choose a pattern in the new case dialog, and a **Variables** list appears under **Description**.
It has one field for each variable the pattern defines, on any element of its argument, showing the variable's name and what it means.
An element detached from the argument, in the sandbox, is not part of the pattern's argument, so a variable defined only there is not listed.
If the pattern gives a variable a value, the field starts with that value; keep it, change it, or clear it.
Every field is optional.
A variable left empty, or cleared, shows its name in square brackets in the new case.
It holds back publishing the new case only while the case's text mentions it; a variable that nothing mentions does not.
A value can be up to 500 characters, and a field shows a count as it nears that limit.
It is saved with the spaces and invisible zero-width characters at either end removed, so a value of nothing else is left empty.
It is saved as text: it is not read for references or markup.
If the pattern is changed while the dialog is open, so that a field no longer matches one of its variables, the platform refuses the request, reloads the variables and says so; what you typed for the variables that remain is kept.
The values fill in the variables themselves, so every mention in the new case shows them and none of the case's text is rewritten.
The pattern is not changed.
A pattern published on Discover asks for its values in the same way, from its own page; see [Use a published pattern](/docs/platform-guide/publishing-and-discover#use-a-published-pattern).

### Set a variable in a case

A case started from a pattern keeps each variable.
A variable that has no value shows its name in square brackets, such as `[system]`, in a dashed outline like a placeholder.
To set it, open the element that defines the variable, give the entry a value, and save.
Every mention then shows the value at once, on claims, strategies and evidence alike.
A value is text: it is shown as written on the card and is not read for references.
The edit dialog's description box keeps showing the name, so that saving never writes a value into the text.

### Variables and publishing

A case cannot be published while its text mentions a variable that has no value.
The status dialog counts them beside the elements still to fill in; see [Publishing and Discover](/docs/platform-guide/publishing-and-discover).
A pattern can be published with its variables empty.

### Export and import

An export keeps each variable's marker, and an import restores it.
A file that holds a variable is written as export version 1.1, and a file that says 1.0 but holds one is refused, as for any named context entry.

## Convert a case to a pattern, and back

A case becomes a pattern in place, and a pattern becomes a case the same way.
Nothing is copied: the one case changes kind.

Open the case and choose **More actions** (the three dots) in the toolbar at the bottom of the editor.
The menu holds **Convert to pattern** on a case and **Convert to case** on a pattern.
The button is shown to the case owner and to anyone with Admin access.
People with View, Comment or Edit access do not see it, and the platform refuses the change if one of them sends the request another way.

Choosing the item opens a confirmation dialog.
The dialog states:

- how many other people (not counting you) and teams the case is shared with, all of whom will see the new kind;
- that health plugin checks and integration access grants stay attached to it;
- how many other cases cite it through away goals or modules;
- that no copy is kept.

Converting changes only the kind.
The elements, comments, sharing, plugin data and integration grants are not touched, and cases that cite it keep their citations.
The away goal and module picker lists cases only, so a pattern does not appear in it.
Because no copy is kept, export the case first if you want to keep both a case and a pattern.

Anyone who has the case open sees a short notice saying who converted it, and their editor reloads to show the new kind.

### When conversion is refused

A conversion is refused, with a message in the dialog, in these situations:

| Situation | What you see |
| --- | --- |
| The case is published on Discover | "Unpublish this case before converting it" |
| The case has a copy on Discover that is still held, live or archived | A message asking you to remove the copy from Discover first |
| The other kind was set a moment earlier, for example by a collaborator | "This is already a pattern" or "This is already a case" |
| The case is in Trash | The case cannot be opened or converted until it is restored |

To convert a published case, unpublish it first.
Publishing and unpublishing are covered in [Publishing and Discover](/docs/platform-guide/publishing-and-discover).

## My Patterns

**My Patterns** in the sidebar opens `/dashboard/patterns`.
It lists the patterns you own and the patterns shared with you directly, in the same card layout as your cases, each marked with a **Pattern** badge.
A pattern that reaches you only through a team is listed under **Shared With Me**.

The page has no **Create new** card.
A line at the top tells you how to make a pattern: start a blank pattern from the new case dialog, or open one of your cases and choose **Convert to pattern**.

**Shared With Me** and **Trash** list patterns together with cases, so the **Pattern** badge is how you tell them apart there.
Restoring a pattern from Trash returns it to **My Patterns**.

## Publish a pattern

A pattern can be published on Discover so that others can use it.
Open the pattern, select its status control in the header and choose **Publish**, as for a case.
Its Case Information needs a description, authors and sector, as for a case.
Placeholders and variables with no value do not hold a pattern back.
On Discover the pattern carries a **Reusable template** badge, and the **Filter by type** list can show patterns alone.
Its page offers **Use this pattern** beside **Download JSON**, and lists the pattern's variables.
Updating and unpublishing work as they do for a case, as described in [Publishing and Discover](/docs/platform-guide/publishing-and-discover#cases-and-patterns-on-discover).
A published pattern cannot be converted to a case while its copy is on Discover.

## Start a case from a pattern

A pattern is used by starting a new case from a copy of it.
Choose **A pattern** under **Start from** in the new case dialog, as described in [Starting a case from a pattern](/docs/platform-guide/building-a-case#starting-a-case-from-a-pattern).

A pattern published on Discover can also be used from its own page.
**Use this pattern** opens the same dialog with that pattern chosen, as described in [Use a published pattern](/docs/platform-guide/publishing-and-discover#use-a-published-pattern).

## Limits and code location

`lib/services/case-kind-service.ts` holds the conversion, the read behind the confirmation dialog and the My Patterns list, and `actions/case-kind.ts` exposes them to the interface.
`components/cases/case-kind-menu.tsx`, `components/cases/convert-case-kind-dialog.tsx` and `components/cases/pattern-banner.tsx` draw the menu item, the dialog and the banner, and `app/(authenticated)/dashboard/patterns/page.tsx` is the My Patterns page.
`lib/case/pattern-variables.ts` reads a pattern's variables and sets their values when a case is started, and `components/modals/_case-create-modal/variables-section.tsx` draws the fields in the new case dialog.
`lib/case/placeholders.ts` holds the rules for when a placeholder is cleared and how many a case has left, `components/shared/nodes/placeholder-badge.tsx` draws the badge, and `components/cases/node-edit-dialog.tsx` holds the switch and the hint box.
